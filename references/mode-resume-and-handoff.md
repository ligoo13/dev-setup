# 模式规程：`resume`（断点续开发）与 `handoff`（会话交接 / 方案互审）

本规程解决「换窗口失忆乱改」、「上下文耗尽被动中断」、「跨 AI 接力断层」以及「多 AI 方案比选/互审互相覆盖」四大痛点。

---

## 一、`resume` 模式：断点恢复与新会话进场规程

当用户新开终端或切换不同 AI 说“继续开发”、“看下进度接着做”或指派新任务时，严禁直接凭猜测改代码，必须按顺序执行以下 4 步：

### 1. 必读上下文链路（固定顺序）
1. `AGENTS.md`（确认红线、目录契约与标准验证命令）
2. `docs/00-ai-hub/STATE.md`（掌握全局里程碑、已完成冻结模块、当前进行中任务与阻塞点）
3. `docs/00-ai-hub/SESSIONS.md` + `git status` + `git branch --show-current` + `git worktree list`（确认当前是否有其他并行终端持有模块锁或独立 worktree）
4. `docs/00-ai-hub/handoffs/` 下按文件名排序**最新的一篇交接单**（若存在，获取上一棒 AI 的细节叮嘱）
5. `docs/06-ops-and-pitfalls/pitfalls.md`（查阅踩坑错题本，避免重复尝试已被证伪的死胡同）
6. 当前活跃迭代文档（如 `docs/04-iterations/iter-01-mvp.md`）

### 2. 输出 ≤5 行的「进度对齐简报」
在修改任何业务代码之前，先向用户发送简短清晰的对齐简报：
```markdown
**【进度对齐简报】**
- **当前分支 / 阶段**：`develop`（或 `feat/xxx`） | 处于 `Iter-01 MVP`
- **已完成（禁改区）**：<简述已验收或已锁定模块>
- **并发锁 / 错题提示**：<无冲突锁 / 终端 B 正锁定 xxx>；已留意错题本中关于 <xxx> 的避坑提示
- **本次拟接手任务**：<具体子任务名称>，预计涉及目录 `<路径>`
- **待确认事项**：<若无歧义写“无，确认后立即开工”或直接按明确指令执行>
```

### 3. 登记会话锁（`SESSIONS.md`）
- 若在主工作区或同分支下操作：在 `docs/00-ai-hub/SESSIONS.md` 的「当前活跃会话表」登记：会话代号/AI 工具名、所在工作区路径、分支名、锁定模块/目录边界、开始时间。
- 若检测到目标模块已被其他活跃会话锁定：**立即停手**并提示用户先确认锁状态或改走独立 `git worktree`。

## 二、`handoff` 模式：停工保存与跨 AI 接力规程

当用户表示“今天先到这”、“上下文快满了，做个交接”、“接下来我换 Codex / Claude 来写代码/审查”时，严格执行以下 5 步闭环：

### 1. 工作区卫生清理
- 将开发过程中产生的任何临时调试脚本、一次性测试输入输出全部移入 `.tmp/` 或直接删除，确保项目根目录与源码目录零垃圾残留。
- 若代码处于可编译/测试通过状态，运行标准验证命令确认状态；若做到一半尚未完工，如实记录卡点（如需保存现场，在当前特性分支提交 `wip(<scope>): 保存 <任务> 阶段现场`）。

### 2. 沉淀踩坑经验（`pitfalls.md`）
- 回顾本次会话是否遇到过环境配置怪癖、第三方库兼容性陷阱、或者尝试过某条走不通的技术死胡同？若有，**立即追加**到 `docs/06-ops-and-pitfalls/pitfalls.md`（写明：现象 → 错误尝试 → 根因与正确解法）。

### 3. 生成独立增量交接单（零合并冲突设计）
- 参考 `docs/00-ai-hub/handoffs/_template.md`，在 `docs/00-ai-hub/handoffs/` 下新建独立文件：
  - **命名规范**：`YYYY-MM-DD-HHmm-<当前AI>-to-<下一棒AI或next>-<简短主题>.md`（例如 `2026-11-26-0130-claude-to-codex-auth-api.md`）
- **交接单必填 5 要素**：
  1. **本次已完成事项与关键变更文件清单**（精确到文件路径）
  2. **验证状态**（哪些命令已跑通，哪些尚未覆盖）
  3. **未完成尾项与当前卡点/风险**（严禁隐瞒半成品或临时 Mock！）
  4. **关键上下文决策说明**（为什么这么写，防止下一棒推翻重写）
  5. **给下一棒 AI 的第一条明确行动指令**

### 4. 刷新全局状态与释放会话锁
- 若当前位于主干集成分支（`develop`）或单线开发：同步更新 `docs/00-ai-hub/STATE.md` 中的进度勾选与「下一步待办」，并将 `SESSIONS.md` 中本会话记录移出活跃表（或标记为 `已交接释放`）。
- *(注：若当前处于多终端并行的独立 `.worktrees/<slug>` 子分支内，为避免日后合并 `develop` 时 `STATE.md` 冲突，仅在子分支内写入独立 `handoffs/` 文件即可，待合并回 `develop` 时统一刷新全局 `STATE.md`。)*

### 5. 输出一键唤醒口令
交接落盘后，给用户提供一句可直接粘贴给下一个窗口/AI 的极简口令，例如：
> 已完成交接存档！你在新窗口对任意 AI 发送以下指令即可无缝续接：
> `请按项目 AGENTS.md 执行 resume 流程，重点读取 docs/00-ai-hub/handoffs/<文件名>.md 后继续推进。`

## 三、对抗比选与交叉审查规程（Adversarial & Cross-Review）

当用户让多个 AI 针对同一需求分别出设计方案，或让 AI B 审查 AI A 写的代码时：

1. **严禁直接改写业务代码或覆盖他人方案**：比选与审查阶段属于只读分析 + 独立文档输出。
2. **独立命名落盘至 `docs/00-ai-hub/reviews/`**：
   - 方案比选命名：`YYYY-MM-DD-proposal-<主题>-<AI名称>.md`
   - 代码审查命名：`YYYY-MM-DD-review-<分支或模块>-by-<AI名称>.md`
3. **审查报告结构（参考 `reviews/_template.md`）**：必须按 `P0 阻断性缺陷 / 安全漏洞`、`P1 逻辑错误 / 契约偏离`、`P2 可维护性建议` 分级列出精确文件路径与行号，并核查是否违反 `AGENTS.md` 四大红线（如暗藏假数据 Mock、漏更接口契约等）。
4. **拍板落地闭环**：待人类最终拍板选定方案后，由执行 AI 将最终决议写入 `docs/02-architecture/adr/`（架构决策）或更新 `docs/04-iterations/` 任务表，再进入编码实现。
